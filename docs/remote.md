# 別の端末をキーボードにする（`/remote/`）

タブレットやスマホに出したキーボードで打つと、**別の端末（Chromebook など）のページに文字が入り、
そちらの Mozc で変換される**。変換エンジンは受け手、キーボードは送り手、という分け方。

- 受け手: https://luffa-lang-labo.dev/remote/ （QR を出す）
- 送り手: https://luffa-lang-labo.dev/remote/keyboard/#r=<room> （QR から開く）
- どちらも隠しページ（noindex・TOP から張らない）

## 何を作らなかったか

「変換エンジンを遠くに置く」（へちま蔓 = かな → 文節/候補 をネットワークに延ばす）は**採らなかった**。
受け手はブラウザだけで IME を丸ごと持てる（単スレッドの Mozc wasm がどこでも動く）ので、
1 打鍵ごとに往復してまで遠くのエンジンを使う理由が無い。ネットワークでしかできないのは
**入力する端末と、文字が入る端末を分ける**ことだけで、運ぶのは入力の側。

## 構成

```
送り手（キーボードだけ）                    受け手（変換エンジンはこちら）
  フリック: FlickEngine → かな/機能キー/文字 ─┐      initLabPage の flickMount に「回線」を挿す
  配列図:   押した・離した（KeyTap）        ─┼─ DataChannel ─→ フリック → onOp（/flick/ と同じ配線）
  配列の宣言（layout）                      ─┘   （LAN 直結）    配列図   → onKeyControl（物理キーボードと同じ feed / feedUp）
  ←────────────── 状態（合成中か・末尾）──────────────────────     配列     → onKeymapControl.load
```

- **フリックは送り手でかなまで解く**（盤面そのものが配列なので）。受け手は `insertKana` / `feedDirect` に注ぐだけ
- **配列図は「理想的な物理キーボード」**。押した・離したをそのまま送り、配列エンジンは受け手で動く。
  打ちかけの文字の表示・同時打鍵・編集操作・確定アンドゥが、物理キーボードと同じ実装のまま効く。
  多指は down / up の順として届くので、時間を見ない配列（薙刀式の相互シフト・AZIK の逐次）は
  回線の揺れに判定が左右されない
- **どの配列で打つかはキーボード側が決める**（`layout` の宣言）。受け手の物理キーボードも同じ配列になる
  （配列エンジンが受け手に 1 つしかないため）
- 候補: フリックは帯（`/flick/` と同じ・打ちながら候補つき）、配列図は物理キーボードと同じポップアップ

## 自由配置（キースイッチを画面に貼る自作キーボード）

配列図の「自由配置」ボタンで、キーを画面のどこにでも置ける盤面になる。キースイッチの片方の端子から
銅線をキーキャップに沿わせ、もう片方をアルミホイルにつないで画面に貼ると、**押したときだけ指の
静電容量が画面へつながってタッチになる**（2026-10-08 に実機で確認）。これを並べれば、基板も
マイコンも無い自作キーボードになる。足りないのは「画面のこの点は、このキー」という対応だけなので、
それを登録して打つ。**受け手は変えていない**（配列図と同じく押した・離したが届く）。

- **登録**: 配列で使うキーを**左上から横へ順に**促し、押された点をそのキーの中心にする。
  文字キー（英字と `; , . /` の 30 キー＋配列が文字を割り当てているキー）が先、機能キー
  （親指の役 → 空白 → BS → Enter → Esc → 矢印 → Shift）があと。親指の役は配列 JSON の
  `roles` / `layouts` から引く（NICOLA は JIS で 無変換・変換、US で 空白・右 Alt）。
  画面はスイッチで覆われて図が見えないので、図ではなく**手順**として作る（ひとつ戻る・飛ばす・
  この段を飛ばす・ここで終える）。置いたキーに重ねて押したら登録しない（同じスイッチを 2 度押した）
- **調整**: iOS のホーム画面のアイコン編集と同じ所作 —— キーが揺れて左上に「−」が付き、ドラッグで
  動かす・「−」で外す。外したキーは「置いていないキー」に並び、選んでから置き場所を押すと戻る。
  ★**キーを押してから空いた場所を押しても動く**（スイッチを貼り替えたあとは画面が覆われていて、
  指でドラッグできるとは限らない）。キーの大きさ（直径）もここで変える
- **打つ**: 押された点に一番近いキー（中心から直径の 0.8 倍以内）として送る。押したあと指が滑っても
  別のキーにはしない
- ★**キーは円**（四角は向きを持ち、スイッチを貼った角度と食い違うと目障り）。押したキーの真上には
  物理キーが乗るので、キーの色だけでなく**キーの外側へ広がる波紋と発光**で返す
- ★**長押しで調整に入る、はしない**（iOS の作法だが、打っている間の長押し = 親指シフトの保持が
  正しい入力なので）。調整はバーのボタンからだけ
- 位置は**ビューポートの CSS ピクセル**。スイッチは画面に物理的に貼ってあるので、画面の大きさが
  登録時と違っても（向き・ツールバー）拡大縮小で合わせない —— 違うと知らせるだけ
- 配置は**物理配置（JIS / US / 格子）ごとに 1 つ**、端末に保存（`lll-remote-free:<profile>`）。
  配列を替えてもスイッチの位置は変わらないので、配列ごとには持たない（刻印だけ替わる）。
  JSON で書き出し・読み込みできる（`format: "lll-free-1"`、`site/src/remote/free.ts` の `FreeLayout`）

### 配列ビジュアライザ（カード）

自由配置ではキーの真上に物理キーが乗っていて刻印が見えないので、画面の空いた場所に**画面全体を縮めた図**を
カードとして出す。置いたキーを同じ位置に小さな円で描き、**刻印は押下の状態に応じて替わる**
（`site/src/remote/layers.ts`）:

- **同時打鍵系**（薙刀式・NICOLA・親指ぴゅん）: 押しているキーの組み合わせにそのキーを足したときの出力。
  親指を押せばシフト面、薙刀式で F を押せば J = が。配列エンジンの展開結果（`chordData` の
  キー名 → ビット・ビットの和 → 出力）をそのまま引く。★ビットは 32 を超える（キーが 34 個ある）ので
  `|` ではなく和で取る
- **かなの逐次系**（月配列・ひたき・いすか）: 待っている打鍵（月配列の `d`）に続けたときの
  出力。待っている打鍵は**送り手で追う**（受け手の状態は往復を待つと遅れる）。配列エンジンの解決を
  簡単になぞるだけの**近似**で、珍しい並びではずれうる（表示だけで、送る打鍵は変わらない）
- **ローマ字系**（`inputBase: "romaji"` = ローマ字・AZIK）は**かなを出さない**。英字のままで、`k` を
  押しても替わらない。綴りは打つ人が知っているので、かなを並べても読む手間が増えるだけ（2026-11-08 に
  一度かなを出す形で作り、msonrm さんの判断で外した）。配列が自分で宣言している刻印
  （AZIK の q = ん・句読点）だけは出す
- Shift を押していれば Shift 面。その状態で何も出ないキーは薄く、替わった刻印は色を付ける。
  カードの隅に、押しているキー（`空白+い`）や待っている打鍵（`k`）を出す
- 打つあいだは指を通す（カードの下にキーがあっても押せる）。**調整のときだけ**掴んで動かし、角の取っ手で
  大きさを変え、「−」で隠す（「配列図を出す」で戻す）。位置と幅は配置の JSON の `card` に入る

あわせて、かなの逐次系では素の刻印も配列の表から引くようにした（ひたきの A = か・月配列の J = う）。

## 回線

**WebRTC DataChannel**（順序保証・再送あり・DTLS で暗号化）。同じ LAN ならホスト候補で直結する。
STUN（`stun.cloudflare.com`）は候補を足すだけで、TURN は持たない = **打った文字は必ず端末間を直接流れる**。

最初の SDP の受け渡しだけ、Worker の中継を通す（`worker/index.js`）:

- `/api/pair/<room>`（WebSocket）。部屋 = Durable Object 1 個 = **2 人まで**・**何も保存しない**・
  1 メッセージ 16KB まで。入退室のたびに `{ t: "peers", n }` を全員へ
- 部屋の名前は受け手が乱数（16 バイト・base64url）で作り、QR の URL のフラグメント（`#r=`）に載せる。
  知らなければ入れない。受け手は localStorage に覚えるので、**どちらを読み込み直しても再接続の手続きは要らない**
- シグナリングは非トリクル（候補を集め切ってから SDP を 1 通で）。受け手が offer、送り手が answer

### メッセージ（DataChannel の上・JSON）

| 向き | メッセージ | 意味 |
|---|---|---|
| 送り手 → 受け手 | `{ t: "op", seq, op }` | `op` = `kana` / `key` / `text`（フリック）、`keydown` / `keyup`（配列図。`tap` = KeyTap、`code` 必須）。`seq` は回線ごとに 1 から |
| 送り手 → 受け手 | `{ t: "layout", keymap, layout }` | 配列の宣言。`keymap` = `/vendor/keymaps/<id>.json`（`REMOTE_KEYMAPS` にあるものだけ）、`null` = フリック。`layout` = `jis` / `us` |
| 受け手 → 送り手 | `{ t: "state", ack, composing, tail }` | フリックのキー表示（空白 ⇄ 変換）と ゛゜小 のため。候補は送らない |

★`tail` は回線を往復するので、打った直後の ゛ に間に合わないことがある。送り手は **ack より後に送ったかな**
を足して先回りする。

受け手は届いたものを文書へ注ぐので、**形を検査してから通す**（`site/src/remote/link.ts` の `parseOp` / `parsePeerMsg`）。
回線が切れたら、押されたまま届いているキーを離したことにする（同時打鍵の状態を残さない）。

## 検査

`site/scripts/browser/check-remote.mjs`（ヘッドレス Chromium の 2 ページ）。接続・フリック・゛゜小・変換と確定・
双方の再接続・配列図（薙刀式の単打 / 親指を押しながら / 同時押し / 変換と確定、AZIK の待っている打鍵）・
連打で拡大しない・候補の出し方・自由配置（登録の順と重なり・打つ・多指・遠い点を拾わない・
読み込み直し・ドラッグ・押して動かす・外して置き直す）・配列ビジュアライザ（シフト面・同時押し・
ローマ字の待っている打鍵・動かす / 大きさ / 隠す）。本番に向けて回すのが基本で、ローカルでは Worker の代役 `relay-local.mjs` を使う
（`wrangler dev` が動かない機械があるため。DEPLOY.md）。

**見えないもの**: 同じ機械の中の 2 ページなので、2 台が同じ Wi-Fi で直結できるか（mDNS・クライアント分離）は
実機でしか分からない。実機の結果（2026-10-08、iPad + Chromebook・家の Wi-Fi）: **体感のラグはゼロ**。
